A laptop's fan has been roaring for a week, the bottom of the case is too hot to rest on your legs, and it slows to a crawl whenever you open more than a few tabs. A technician would know where to look. Someone learning repair usually doesn't get the chance to find out, because finding out means opening up a machine they can't afford to break.

RepairVerse is a repair simulator that runs in the browser. You get a device in 3D, a symptom, and a problem to solve. You look around, form a theory, pick a fix, and find out whether you were right and why.

Built for the Aholo Global 3D AI Hackathon, with device models generated by Aholo Lux3D.

## Why RepairVerse exists

Repair is learned with your hands. You get good at it by opening devices, recognising parts, and making a few wrong calls along the way. The trouble is that each of those steps costs something. Spare laptops and phones are expensive. Not everyone lives near a training centre or knows someone who'll let them watch over their shoulder. And a wrong call on a working device can turn into a bill.

Video tutorials help, but they only let you watch. You can't turn the device around to see what's behind a part, and you can't try the wrong fix to see what happens.

So there's a missing step between watching a repair and doing one on real hardware. RepairVerse is meant to be that step: somewhere to practise the thinking behind a repair before the stakes are real.

## What a session looks like

1. **Pick a device and a mission.** Each mission starts from one complaint, like "it keeps overheating".
2. **Look around the model.** Rotate it, zoom in, open it up.
3. **Inspect the parts.** Clicking a marked component tells you what it does and what state it's in for this scenario.
4. **Decide what's wrong.** Choose the most likely cause from a few plausible ones.
5. **Choose a fix.** Some options solve the problem, some don't, and some make it worse.
6. **See how you did.** Every choice comes with an explanation, and the mission ends with a score.

## Mission one: the overheating laptop

The first mission is built around a fault that almost everyone has run into.

The learner is told that a laptop gets very hot, its fan is loud, and it slows down under load. They open the 3D model and follow the cooling path: the intake vents, the fan, the heat pipe, the heatsink fins, and the processor underneath. Some parts look fine. The fan and vents are clogged with dust. The learner has to connect the symptom to the cause, rule out the red herrings (a failing battery or a software problem, for example), and pick a sensible first repair.

By the end, a learner should be able to:

- name the parts of a laptop cooling system and say what each one does
- explain how blocked airflow leads to heat, fan noise and throttling
- rule causes out with evidence instead of guessing
- choose a reasonable first fix and explain why it comes first

A note on accuracy: the scenarios and repair guidance are written by us for teaching. They are deliberately simplified and are not a substitute for a manufacturer's service manual.

## Where Lux3D fits

Without Aholo Lux3D, every device would have to be modelled by hand, and a small team could only ever ship one or two missions. With it, we can describe a device in a prompt or give it a reference photo and get back a 3D model to build a lesson on.

The pipeline:

```text
prompt or reference image  →  Lux3D model  →  3D viewer  →  hotspots + mission  →  reused for the next mission
```

**Generating the model.** We prompt Lux3D for the device ("a slim 15-inch laptop, lid open") or give it a reference image, and keep the result that best suits teaching.

**Bringing it into the viewer.** We export the model, convert it to glTF/GLB if needed, and load it into a React Three Fiber scene with lighting and orbit controls.

**Adding hotspots.** This is where our work starts. We place markers at chosen points on the model and attach content to each one: what the part is, what it does, and what condition it's in for the current scenario. If a mission needs internals that the generated model doesn't show clearly, we arrange or design those ourselves.

**Running the mission.** Each mission is a data file we write by hand. It lists the symptom, the hotspots involved, the possible causes, the repair options, and the feedback for each choice. A small mission engine reads that file, tracks what the learner has done, and works out the score.

To be clear about the division of labour: Lux3D gives us the 3D model. It doesn't write repair steps, decide what's broken, or produce mechanically accurate internal components. All of that is ours.

Models are also reusable. Once we have a good laptop, the same asset can carry a second mission (a failing hinge, a swollen battery) without generating anything new.

### Scoring

Each mission starts with full marks. Wrong diagnoses and repairs that make things worse cost points, and asking for a hint costs a little. Getting there by inspecting the right parts first earns more than guessing your way to the answer. The aim is to reward reasoning more than luck.

## Features

- A 3D view you can rotate, zoom and pan in the browser
- Clickable hotspots on the components that matter
- A diagnosis step built around a real symptom
- Repair choices, with a hint if you're stuck
- Feedback on every choice as soon as you make it
- A score at the end of each mission
- Runs in any modern browser, with nothing for learners to install


## Running it locally

You'll need a current LTS version of [Node.js](https://nodejs.org/).

```bash
git clone https://github.com/ladicodes/RepairVerse.git
cd RepairVerse
npm install
npm run dev
```

Then open [http://localhost:3000](http://localhost:3000) and pick a mission.

For checks, every page route, the mission rules, and how to drop in a Lux3D export, see [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## The hackathon

RepairVerse is our entry to the **Aholo Global 3D AI Hackathon**. We wanted to use AI-generated 3D for teaching rather than decoration, and repair seemed like a good fit. It's a practical skill that's hard to learn without hardware, and a 3D model is a cheap stand-in for hardware.
